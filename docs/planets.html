Planet virtualization & procedural terrain

A planet is stable mathematical identity; visible surface geometry is materialized on demand.

Detailed Phase 2B design and validation →

Cross-face neighbours, atomic 2:1 balancing, geometric stitching and common-refinement morphing are implemented. Vertical skirts are no longer used.

Cube-sphere quadtree

Tiles use a stable face/level/x/y address. All six faces remain covered; a budget limit retains coarser parents. Each render patch reuses a 32×32-cell grid. Adjacent levels differ by at most one, including across cube edges and corners.

rotating-frame camera → balanced logical cut → common refinement → source/target triangle reconstruction → stitched edge → WebGPU

Current LOD metric

The selector uses projected patch footprint with hysteresis and a max-heap. It does not yet use a certified bound on terrain approximation error. The higher-level SSE goal remains a later improvement.

projectedFootprint ≈ radius × angularSpan × focalScale / distance

Current terrain and materials

The runtime uses seeded fractal-noise displacement and simple height-based ocean/land/rock colors. Lighting normals are now derived from the final displaced/stiched surface using fragment derivatives, with the radial normal retained only as a degenerate fallback. Tectonic geology, drainage, erosion, climate-aware materials and microdetail below are design targets, not implemented simulation.

planned synthesis stack ├─ continents / basins / tectonics ├─ mountains / plateaus / craters ├─ ridges / valleys / drainage / erosion ├─ outcrops / dunes / boulder fields └─ micro normals / roughness
